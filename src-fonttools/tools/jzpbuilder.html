How this tool works

This page edits the JianZiPu font's layout geometry (layouts.json: where each glyph area sits inside a composed word) and component metadata (components.csv: which SVG glyphs exist and which layout areas each one can occupy), then can build the actual font from them. Nothing here talks to Figma — it works entirely from whatever's already in src-fonttools/inputs/.

Import / Save / Export (menu bar, top of the page)
  • Import ▾ — load a layouts.json, components.csv, or SVGs from disk to replace what's currently loaded in the browser. On page open, this happens automatically from src-fonttools/inputs/.
  • Save ▾ — layouts.json, components.csv, and svgs each write your in-browser edits straight back to the real files under src-fonttools/inputs/ (svgs to one file per glyph, inputs/svg/<glyph_name>.svg); Save All does all three in one request. Needs the Dev Server running (see below) — without it you'll get a "no dev server running" message.
  • Export ▾ — downloads layouts.json (with its yd field recomputed from y/h — yd is the baseline-flipped offset the font's GPOS rules actually use, so it's kept in sync automatically; not something you'd edit directly), components.csv, or svgs.zip (every loaded SVG) to your Downloads folder. Works with no server at all, but you'd have to move the file into src-fonttools/inputs/ yourself afterward.
Undo/Redo & zoom (toolbar)

Edit ▾ has Undo/Redo (also Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl+Y) — most edits (drags, area/layout add/delete, glyph assignment, CSV field edits) are one undo step each. The − / percentage / + / reset group next to Help zooms the canvas (mouse wheel over it works too); drag on empty canvas to pan. Area name labels grow their source font size when you zoom out, so they stay readable instead of shrinking away to nothing.

Layouts (left panel) & Areas (canvas)

Each entry in the left Layouts list is one named layout (layout_gou, layout_vertjzp3, ...) from layouts.json. Selecting one shows its areas as boxes on the canvas — drag to move, drag the corner handle to resize, arrow keys to nudge (shift = ×10), or edit the numbers directly in the Areas panel on the right (under Tools). layout_cuo_left/right (and their 2/3 variants) are two halves of one 撮 chord, so selecting either one also shows the other as a dashed, read-only preview 500 units to the right — that's what the real font renders side by side.

The Layouts (Double Sided) section below it is a dedicated left/right picker for those same six cuo layouts, so you can mix and match any left variant with any right variant (e.g. preview layout_cuo_left3 paired with layout_cuo_right) instead of only ever seeing the fixed left↔right, left2↔right2, left3↔right3 pairing. Pick one from each column to preview a custom pairing; picking just one side falls back to that layout's normal fixed pair. Selecting any other (non-cuo) layout from the main Layouts list clears both picks.

Tools (right panel)
  • Test random components — fills every area of the current layout with a random valid glyph, so you can eyeball fit across many shapes quickly. It respects the font's actual rules, not just "any glyph tagged for this area": an area_right slot only ever gets a glyph from that layout's own right-hand-technique family (e.g. layout_gou3 only ever picks lg_gou/lg_da), a layout_vertjzpN row is either its area_char glyph or its area_left+area_hui pair — never all three at once — and a cuo pair gets filled on both sides together.
  • Clear Components — empties every area's assigned glyph for the current layout only (other layouts and the loaded SVG library are untouched).
Area → components panel (bottom of the page)

Click any area on the canvas to see every glyph whose components.csv row includes that area, as clickable chips. Click an unassigned chip to assign it to that area; click the already-assigned one again to unassign it. For area_right, chips outside the current layout's family are shown grayed out and unclickable rather than hidden, so it's clear why they're not valid there. Clicking a chip also opens an inspector on the right where you can edit that glyph's area memberships and spellings directly — those edits live in the in-memory CSV until you Save/Export it. Use Add New SVG to bring in another glyph: it opens a modal listing every already-loaded SVG as a click-to-select chip (multi-select, already-assigned ones pre-highlighted) — "Add selected" adds them all to the current area (creating a minimal CSV row for any that don't have one yet). The modal's own Upload SVG button reads a file straight into memory (no dev-server round trip); if its name collides with one already loaded, you're prompted to rename it (e.g. foo → foo_2) before it's added. Either way, nothing reaches disk until you use Save ▾ > svgs (or Save All).

Build Font

Opens a modal listing every input file python3 -m jzpbuild would read, prefilled with the real defaults — edit any path to build from somewhere else just for that one run. Build Font always reads from disk, never from what's currently loaded in this page, so use "Save Configs" first if you've made changes you want included. Needs the Dev Server (below); on success you'll get a link straight to Font Tester to try the result.

Dev Server

Several features above (real auto-load, Save Configs, Build Font) need a small local server running, since a plain file:// page can't read/write files on its own or run a build. Start it with:

cd src-fonttools && python3 -m jzpbuild.devserver

then make sure you're viewing this page through http://127.0.0.1:5713/tools/jzpbuilder.html (not a file:// path) — see src-fonttools/README.md's "Dev Server" section for the full list of what it adds.
