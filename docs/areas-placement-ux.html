Where Areas goes

Wireframes for docs/AREAS-PLACEMENT-UX.md. Design only: no app code or data changed. Real data from design.json: 11 areas, 4 word types.

Recommendation: drop the Areas tab. Don't add a ninth panel. The Glyphs tray on Layouts already shows "the area of the selected part", so it grows one line (name, box, used in) and becomes the Area panel. The big member grid moves to the Glyphs screen, where the sidebar already groups by area.

  • Box size is a layout edit. On Layouts you see what it moves while you type; on Areas you can't.
  • Membership is edited in three places today. The Areas grid is the third, and it nearly matches Glyphs with an area group picked.
  • What only Areas does (name, box, advance, new, delete) is too small to need a tab.
