Information architecture & proposal flow

1 2 3 4 5
  1. 1Roles are entry points, not separate logins. One person can hold all three. in the header, is the "current role" a mode you switch (changes nav), or just a label of where you are?
  2. 2is Requester implicitly granted to every signed-in user, so Admin only needs to grant Calligrapher / Layout Manager / Admin? Drawn that way.
  3. 3can a rejected proposal be reopened as a draft (keep the work, fix, resubmit), or is reject terminal and you start a new one?
  4. 4Build failure does not un-approve. The proposal stays "approved" with a failed build badge; an admin can retry. should a failed build auto-notify the author?
  5. 5Proposal is the single hub: every Calligrapher / Layout Manager save lands in one, Requests can be linked to one, Admin approves from one. Drafts are private to the author until submitted.

  1. 1Identity row mirrors one components.csv row: name, key, area (sets the box size), Chinese character for Chinese input. should the Calligrapher be allowed to change key/area here, or is that the Layout Manager's job and this row is read-only?
  2. 2Three ways in, one canvas. Upload = drop an .svg. Trace = drop a photo/scan, tune threshold, get paths. Draw = start from an empty box. All three end on the same Draw/edit tab.
  3. 3Toolbar, top to bottom: select, node edit, pen, cut, rectangle; flip H, flip V, scale, simplify; undo, redo. Kept deliberately small. is pen-from-scratch really needed, or is "trace then tidy nodes" the realistic workflow?

  1. 1Layouts from layouts_data.json: default_jzp, chord_left, chord_right. Selector keys match the real `selector.contains`. is vertical a separate layout here, or a variant flag on every area as in components.csv today?
  2. 2Canvas shows the areas of the selected layout composed into one test word. Click a box to select the area; its relationships highlight in the table. Dragging a box edits the gap number directly. Toggle boxes / glyphs / gap arrows.
  3. 3Order list mirrors `order`: drag to reorder, optional checkbox, exactly one pivot radio. Required areas (right, string) cannot be optional. Area sizes are shared across layouts so they sit on the left, not here.
  4. 4Relationship row = axis, element, base (or canvas), base edge, gap. A gap is a number or "by glyph": the expanded editor is the conditional table, rows evaluated top to bottom with a final "otherwise". Conditions can name base glyphs, element glyphs, or both. is top-to-bottom first-match the right rule, or should overlapping conditions be an error?
  5. 5Centering mirrors `vertical_center_order`: pills are groups, "left + hui" is one group. Drag pills between groups. Horizontal centering is one switch. is horizontal centering per layout or global?
  6. 6Test words accept both key strings (lk1) and Chinese input (大七勾一). Rendered live from the unsaved rules. "random" reuses the old "test random components" idea.
  7. 7Size badge: relationship count, estimated generated rule count and lookup bytes against the 64 KB OpenType ceiling. Turns to a warning at 80%, blocks submit at 100%. Numbers are illustrative.
