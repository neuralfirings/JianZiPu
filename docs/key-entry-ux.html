Typing, inside Glyphs

Wireframes for how each glyph is typed: the editable columns of src-fonttools/inputs/components.csv, for guqin players who have never heard of GSUB. Revised, and decided: the owner's answers are in §12. Spellings now live on the Glyphs screen, as a Tiles | Typing switch plus a Typing column in the bottom inspector. The separate tab from the first version is superseded (see the verdict). All rows are real rows from today's CSV unless marked hypothetical. Same look as glyph-editor-ux.html.

AOne glyph = one tile = one row. Glyphs gets a Tiles | Typing switch. Typing shows the same glyphs as a table, so you can compare spellings across glyphs.
BThe inspector shows what the view doesn't. In Tiles, its new Typing column holds the spelling fields. In Typing, the row is the editor, and the inspector shows Try it, What changes and Issues.
CShared on purpose = a vertical pair, shown as a blue ⇄ link. Any other shared spelling is a clash, shown in red, and Save waits until it's fixed.
DSpellings use the app's normal Save, with undo and the unsaved count, just like area and layout edits. The data stays in components.csv.

Why the first version's reasons no longer hold. "The tile grid can't compare across glyphs" and "clashes span areas" are both answered by the Typing view, which is a table across all parts. "Try it would crowd the inspector": the inspector is full-width, and Try it gets its own column. The data check settles the rest: filename = glyph_name in every row (md_tang's is blank), and a glyph is its SVG file, so a spelling row is a property of a tile, just like its parts, which the inspector already edits. View name: "Typing", the same word as the inspector column, so it means one thing. "Key Entry" sounds like data entry, and key already means a keyboard key and a design.json key.

!Why Save waits: a clash written to disk makes the next build fail, and in the hosted phase a proposal with a clash would fail its preview build. Clashes come only from typing edits you're making right now, so fixing one takes a few seconds (undo, or change one cell). The design's Save already refuses an invalid design, and this works the same way.
!What counts as a clash: the same Letters, Short form (one shared namespace) or 简体 / 繁體 value on two glyphs that aren't each other's vertical form. Errors that also block Save: Letters with characters other than a–z A–Z 0–9 (the build can't spell -), Letters that start with a digit, a non-Chinese character in 简体/繁體, and a reserved character alone (点 點 徽 。 ，, which mark positions).

12 · Decisions, left out on purpose, open questions

Decisions

  1. Inside Glyphs, not a tab of its own (supersedes the first version). A Tiles | Typing switch. Nav stays at 5.
  2. The inspector shows what the view doesn't. Tiles: Glyph · Typing fields · Try it. Typing: Glyph · Try it / What changes / Issues. One editor for each value on screen.
  3. Sidebar groups by part (Right hand, Chords, Left hand, Numbers, Modifiers, Characters, Position decimals), plus Typing filters. Both views share them.
  4. Selection, search and sidebar filter carry over when you switch views. The view is in the URL and remembered.
  5. Tiles show the first working spelling and ✕ ⚠ · badges. "Typing keys →" goes away.
  6. Decimals: no spelling fields. The inspector shows their pattern. In Typing they are one folded group with read-only rows.
  7. Vertical pairs are a link (⇄), edited together. Any other shared spelling is a clash.
  8. Clashes and invalid spellings pause Save. Warnings and hints never do.
  9. Try it + What changes use unsaved spellings (a GSUB-only recompile in memory, about 0.5 s). A round-trip check on every change.
  10. One Save, one undo for design and spellings. Hash check per file.
  11. Keep the CSV, and drop ID, keys and filename.
  12. Bulk = paste ranges in Typing + Import/Export CSV under Glyphs ⋯.
  13. Areas keeps a read-only "Typed as … Edit in Glyphs →" line. edge_cases.fea is shown read-only in plain words. glyphRename.csv is not shown.

Left out on purpose

  • A separate Typing / Key Entry tab (the first version).
  • Spelling fields in the inspector while in the Typing view (the same value would be editable twice).
  • Editing edge_cases.fea or glyphRename.csv (engineer files).
  • A free-form typing-rule builder ("after 名, 七 means…").
  • Adding number or symbol spellings (built into the generator).
  • Choosing which glyph wins a shared spelling: the horizontal glyph always beats its vertical form.
  • Editable rows for the position decimals.
  • Renaming glyphs, and per-row history (git is the history).
  • Proposals and review (the hosted phase). The change list sentences are written to become a proposal summary.

Owner decisions (2026-10-17)

  1. Column labels: Glyph Name, Latin Entry, Latin Entry (Alt), Number/Symbol, PinYin. 简体, 繁體 and Vertical form as drawn. The view stays "Typing".
  2. Glyph Name is the ID. Drop keys, ID and filename.
  3. Sidebar groups by area (design.json areas and order) in both views. A glyph in several areas appears in each. Decimals fold inside 徽 position.
  4. A clash pauses all of Save, with a clear message and one-click fixes.
  5. Vertical forms store only the link, plus any spelling of their own. Inherited spellings show greyed.
  6. Spellings with a digit get a generated rule, so xi4 and fu4 work.
  7. Missing characters show in red in every preview, drawn by an installed font. No on-the-fly characters, no error glyph.
