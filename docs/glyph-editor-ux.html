Glyph Editor

Wireframes for editing, importing and tracing glyph outlines in the JZP Font Builder. It is a touch-up and import tool, a small Figma vector-edit mode built on Paper.js, and not a drawing app. It writes inputs/svg/<name>.svg and nothing else. Same look as panel-layout-ux.html.

AEdit appears under a glyph tile when you point at it or select it. It opens the editor at /glyphs/lg_gou/edit, which takes over the main area. The app header stays.
BOne canvas, one pointer tool. Select a shape and its points are already editable. There is no separate point mode. Pen, pencil and two basic shapes make up the rest of the tools.
CCompare in translucent blue: a dot at the font's reference weight, any other glyph, or this glyph's last saved version. You can't select them and they are never saved.
DSave glyph writes the SVG file at once. It is separate from the app's Save, which writes design.json. Layouts and the Tester show the new outline right away. The built font changes after the next Build.

Your question: take over the main window, or open as a modal?

Take over the main window, as its own route: /glyphs/<name>/edit and /glyphs/new. The app header and section nav stay visible. A modal would work for a quick nudge of one point, but it fails on most of the points below.

1Reference dot: a circle as wide as the reference weight, filled translucent blue. Drag it over a stroke: if the stroke shows past the dot on both sides, it is heavier than the font's norm. One dot, placed in the middle of the view the first time and remembered after that.
2Another glyph: ghosted at 1:1 units from the box's top-left (or centred, for boxes of different sizes). Because units are the same everywhere, a 350 glyph next to a 660 glyph shows a true weight comparison. Defaults to a sibling from the same area.
3Last saved: a dashed blue outline of the file on disk, showing what you changed. It is an outline rather than a fill so it doesn't hide the other two.
4All three are drawn on top of the glyph, translucent, and ignore clicks, so points stay editable through them. They are never saved and never exported. Blue fill always means "compare". Selection uses lines and handles only.

Does one reference weight make sense? Yes, with one caveat.

SVG units are font units for every glyph (the build doesn't scale), so 38 units is the same ink width on the page whether the glyph sits in a 200, 350, 660 or 1000 box. A single number therefore keeps all glyphs the same colour on the page. The caveat: brush strokes swell and taper. The reference is for the body of a stroke (where the dot should just cover it), not for entry points, hooks or hairline tails. The hint says so: "Match the middle of main strokes. Tapers can be thinner."

  • Union, Subtract, Intersect, Exclude from Paper.js (unite, subtract, intersect, exclude). They are enabled only with 2 or more shapes selected. Pointing at a button previews the result in the canvas before you click.
  • Which shape cuts? With no layers panel, the rule is drawing order: the newest shape cuts the older ones, which is almost always the shape you just drew to cut with. If the preview looks backwards, ⇧ while pointing swaps which one cuts.
  • Unlike Figma, the result is final (a new outline, not a live boolean group). Undo is the way back. That keeps the file a plain list of shapes and matches what the build does anyway.
  • The build already merges overlapping shapes, so Union is never required. It is for tidying the outline before editing points.

1The editor has its own Save. Save glyph writes inputs/svg/lg_gou.svg at once, through a new PUT /api/svg/<name> that includes the hash of the file as it was loaded. A file is its own unit, and a draft of curve geometry has no place in design.json's undo history. The cost: two Saves exist. The labels (Save glyph / Save design) and the header chip keep them apart.
2Undo is per editing session: every point drag, tool stroke, import, trace and operation is one step, and the tooltip names it ("Undo: Thicken +4"). Saving doesn't clear it, so you can save, look at Layouts and still undo. Leaving the editor clears it.
3Discard goes back to the last saved file. It can be undone: a toast says "Discarded 6 changes · Undo".
4A browser draft (IndexedDB, one per glyph) keeps unsaved edits through a crash or reload, with the same Restore/Discard banner as the design draft.
5What gets written: one <path fill="black"> per shape, the area box as viewBox/width/height, coordinates rounded to 0.1 unit, open lines outlined. Nothing else: no ids, no Paper.js metadata. Git is the history; the editor keeps no versions.

10 · Decisions, left out on purpose, open questions

Decisions

  1. Takeover route /glyphs/<name>/edit and /glyphs/new, with the app header kept. Dialogs only for small, single-decision steps.
  2. Edit under the tile on hover/focus and on the selected tile. Double-click or Enter also opens it. The inspector gets Edit outline, Replace from file…, Trace from image….
  3. Own Save. Save glyph writes the SVG at once (hash-checked). Glyph undo is separate, and the header's undo is hidden on this route.
  4. One pointer tool. Selected shapes show live points. No point mode, no transform box (numbers instead), no layers panel.
  5. Open paths are lines at the reference weight with round ends. Outlined on demand or on save. The file only holds filled shapes.
  6. Reference weight is one font-wide number in design.json, set on the Glyphs screen. The editor's dot can change it for the session only.
  7. Compare = translucent blue: dot (filled), other glyph (filled), last saved (dashed outline). On top, click-through, never saved.
  8. Ops preview live with a grey dashed "before". Simplify = 1 slider. Thicken = total width change, selection or whole glyph. Booleans: the newest shape cuts.
  9. New glyph = name + area + start. Names never overwrite. The area is joined on first save, as a design change.
  10. Trace images stay in the browser (per glyph) for re-tracing, not in the repo.
  11. In-context strip in the editor (3–5 words, live rules, unsaved outline) plus a link to the Tester.

Left out on purpose

  • Layers, groups, colour, opacity, text, gradients, images in the output.
  • Pressure or variable-width brushes. The pencil draws a line of one weight.
  • A separate point-edit mode and Figma's live boolean groups.
  • A transform box on the canvas (scale/rotate via numbers and Fit to box).
  • Renaming a glyph (it touches the file, components.csv and design.json; it belongs to the Areas screen later).
  • Changing area membership or typing keys inside the editor.
  • Versions, proposals and review (the hosted phase).
  • Batch import of many SVGs at once (see questions).
  • Auto-measuring stroke weight.

Open questions

  1. Edit button on every tile all the time, or hover + selected as drawn?
  2. Default reference weight: which number? (Today's glyphs sit around 30–45 units. Your measurements will settle it.)
  3. Should trace sources be kept in the repo (inputs/sources/) so the brush originals survive a browser reset?
  4. Is the pencil (freehand + simplify) worth having next to the pen, or is "trace a scan, then tidy" the real workflow?
  5. Drop many SVGs at once (a Figma export of a whole set): a batch import list, or one at a time?
  6. Should the Glyphs tile show a small weight badge (measured stroke width vs the reference)? It needs a raster measurement, which is more than Paper.js gives for free.
  7. Subtract by drawing order, with ⇧ to swap: clear enough without a layers panel?
