Design guide

How the JZP Font Builder looks and behaves, on a computer and on a phone: the principles, the rules for each part of the screen, the tokens and the components. A snapshot of the design system from 2026-10-23.

Principles

Build every screen as quiet paper around loud glyphs: grey paper (bg-app, bg-panel), near-black ink (ink), and one seal-red (accent). The glyphs are the content; chrome never competes with them.

Content fundamentals

  • Write plain, precise sentences for guqin players and calligraphers, not engineers. Say "String's top edge sits at Right hand's bottom edge", not "anchor offset y". Name the thing, then the number.
  • Sentence case everywhere ("Open in Glyphs", "New rule", "Keep this change"). Chinese labels sit beside Latin ones, never instead: 泛音 fy, 徽 position, 急/绰 modifier. Use 简体 and 繁體 exactly so.
  • Address the person as "you" only in help and dialogs. Labels are nouns, buttons are verbs: "Save", "Skip", "Build font".
  • Say what changed and what is safe: "3 spellings clash with 勾 (k). Nothing was saved." Errors name the item and the fix; never "Something went wrong".
  • Numbers carry units or a source: -120 (rule 3), 1229 rules · 46 KB, 497 skipped. Use the arrow → for navigation links ("Open in Glyphs →") and the middle dot · to separate facts.
  • No emoji. No exclamation marks. No marketing voice: this is a workshop.

Visual foundations

Colour. Three roles. Paper: bg-app behind everything, bg-panel for docks, bg-canvas only under glyphs. Ink: ink, ink-muted, glyph. Seal: accent, cinnabar red, for the anchor part, the highlighted component inside a spelling, and destructive actions. Link blue (link) is for links, focus and selection. Never spend accent on decoration; it is one stamp per view.

Status has its own four colours, each always paired with an icon and a word, never colour alone: jade status-saved, ochre status-draft, cinnabar status-danger, blue status-info. See states.md.

Type. Three working faces. Headings in display (EB Garamond): pen-derived, early-printing proportions, the readable descendant of calligraphy, used for the title, section heads and panel titles. Everything else in serif (Literata), the face of the public JianZiPu font page, at 13–14px. Typed spellings and ids in mono. Chinese pairs with Noto Serif SC, the Song (宋体) printing style, the same lineage as Garamond: Chinese is never set in a different voice from the Latin beside it. Where people type Chinese, use sans-cjk (cjk-input) so characters line up with the preview. Traditional text carries lang="zh-Hant" and takes serif-tc. A brush or script face is never used for anything people must read or edit.

Type scale is fixed: title 32, heading 22, panel-title 16, body 14, label 13, small 12, caption 11, code 13, code-sm 11. Nothing below 11px. Keep Latin and Chinese on the same baseline, and give Chinese lines the body line-height (22px) so mixed lines do not jump.

Space and density. The default is compact: control-md (28px) controls, space-4 between controls, space-5 panel padding. A "comfortable" density raises controls to control-lg and gaps one step; use it for testers' first-run screens. On a phone every control is one size up (control-sm 28, control-md 36, control-lg 44) and main actions are control-touch (44px); nothing tappable is under 24px. Pick spacing only from space-1…space-9.

Edges, not shadows. Panels and docks are separated by 1px border and bg-panel; only things that float (menus, toasts, dialogs, a dragged dock) take shadow-float, shadow-modal or shadow-drag. Radii are almost square: radius-sm 2, radius-md 4, radius-lg 8, radius-pill for status pills and the typing field, as on the font page.

Layout. Desktop first: top bar, a left dock, the canvas in the middle, a right dock. Docks resize between dock-min and a half screen, and collapse to their title row. Below 760px is a phone: a one-row top bar, bottom tabs, the canvas pinned on top with the panels as sections under it, tables as cards. Every screen declares whether it works on a phone; the default is "needs a computer", shown with the NeedsComputer note. See phone.md.

Motion. 120ms ease-out for hover and selection, 200ms for dock collapse. Nothing bounces; no motion on the canvas except drag feedback. Respect reduced motion.

Focus. Every control shows a 2px solid focus ring with a 2px offset on keyboard focus. Never remove it.

Themes. Light is grey paper and ink. Dark keeps the canvas as ink-on-paper inverted (bg-canvas goes dark, glyph goes light), so a glyph is always the brightest thing on screen.

Iconography

Icons are 16px line icons, 1.5px stroke in currentColor, square caps: ≡ drag, ▸ disclosure, ✓ saved, ! warning, × close, → link. Use text symbols where they exist. One icon never stands alone for a state: it comes with its word. No emoji, no filled mascots. The brand has no logo mark here; set the name in title. A cinnabar seal (印章) stamp, a square accent tile with one Chinese character in reversed type, may sit beside the title once per product.

Where to look

Everything below 760px (the phone shell, touch sizes, press and hold, the "needs a computer" note): phone.md. Each component has a README and a live preview.

On a phone

Desktop is the Builder. A phone gets the jobs that suit it (reading the help, following your Change Requests, trying words, editing a glyph's spellings, adjusting layouts by touch) and says plainly when a tool needs a computer. Everything here applies below one breakpoint and nowhere else; the desktop layout, sizes and tokens never change for it.

Breakpoint

One breakpoint: narrower than 760px, written @media (max-width: 759.98px). There is no second phone size and no tablet layout of its own, so a tablet at 768px or wider gets the full Builder. The 760–1100px "one dock at a time" arrangement in layout-and-density.md is a desktop rule and is unaffected.

Screens

Every screen declares one of two things: it works on a phone, or it needs a computer. The default is "needs a computer", so a new screen is safe on a phone until someone decides otherwise.

  • Works on a phone: Glyphs (Tiles and Typing), Layouts, Build & test, Help, Your Change Requests, Your changes (a tester's own Review), Sign-in.
  • Needs a computer: the glyph editor and New glyph, Review of other people's changes, Release, Import / Export of the design.
  • Left out on a phone rather than noted: Typing's paste of ranges and CSV import and export, New glyph's button, the Areas column, Structure's Advanced switch, and Structure's grips for reordering a word type's parts (a structural edit, like the Advanced ones). Those controls are simply not shown below 760px.

Phone edits go through the same actions as desktop ones, so checks, locks and undo exist once.

Shell

  • Top bar. One 48px row on bg-panel: the seal, the screen's name in display at heading size (22px) with an ellipsis when it runs long, a short StatusPill ("Saved", "1 unsaved"), Undo and Redo on Glyphs and Layouts only, then More. Icon buttons are 44px wide.
  • More holds everything else the desktop bar shows: the draft or local-files note ("Your draft: only you see it. The font itself doesn't change."), the font budget ("Font budget: 1731 rules · 69 KB"), the import and export items, and the account with Sign out.
  • Bottom tabs. 56px tall plus the safe area, on bg-panel with a 1px border top edge. Each tab is a 20px icon over a caption word in ink-muted. The current tab is ink on sel-bg with a 2px sel-border top edge and aria-current="page". The tabs are Glyphs, Layouts, Try (Build & test), Requests (online only) and Help.
  • Save bar. A 52px bar sits above the tabs only while something is unsaved (online, also while a save failed or you're offline). It holds the StatusPill on the left and the one primary Save on the right; while it shows, the top bar drops its pill.
  • The keyboard. While a field has the keyboard, the tabs and the Save bar step aside, and on iPhone (which doesn't shrink the page for the keyboard) the Builder shrinks to the part of the screen still visible.
  • Toasts sit above the tabs and the Save bar, never over them.

Density

Every control is one size up: control-sm 28px, control-md 36px, control-lg 44px, the size of control-touch. Panel headers are 44px. Text fields, selects and text areas use 16px type so iPhone doesn't zoom into the field being typed in.

Targets: 24px is the minimum for anything tappable (WCAG 2.5.8), 44px (control-touch) for main actions, tabs and the top bar's icon buttons.

Tooltips

There is no hover. A tap on a button with a tooltip shows it as the finger lifts, beside the button, for long enough to read: 1.5s plus 40ms a character, at most 6s. The next tap or a scroll hides it. Icon-only buttons keep their aria-label, and say what they do with it.

Panels

On a phone a dock is one column. The canvas (or the screen's centre) is pinned on top at min(52dvh, 460px), on bg-app with a 1px border under it, and the panels are sections under it that scroll.

  • Sections come in a fixed order, the one a tap is most likely to open first: Spacing first on Layouts, Selection first in the glyph editor.
  • No grips, no moving between docks, no resizing. A section folds and unfolds by its header.
  • Tapping a part on the canvas opens its panel (Spacing) and scrolls it in just under the canvas.

Canvas by touch

A finger can't hover and has to scroll, so the canvas waits before anything moves.

  • Swipe scrolls the page. Tap selects a part, on release, and opens its Spacing.
  • Press and hold for 400ms, moving no more than 8px, to lift a part. Moving more than 8px first gives the gesture to scrolling.
  • The hold ring. While the finger holds, a ring 60px across fills around it in ov-active, 4px wide. It appears only after about 100ms, so quick taps don't flash it. Under reduced motion it appears whole, without filling.
  • Lifted. The part's box takes a 4px ov-active outline, a sel-bg fill and shadow-drag. Where the phone allows it there is a short vibration (10ms); iPhone web can't vibrate, so the outline carries it alone. From then on the finger drags the part and the page doesn't scroll. Release ends the drag as one undo step.
  • Handles (the ○ link handles) follow the same hold, and get a 24px target around the drawn handle.
  • Nothing over the finger. No label or popover follows the finger: it hid the glyphs. The gap shows where it always does, in the measurement label (-120 (rule 3)) and in the hint bar.
  • Nothing around the canvas changes size during a drag, or the canvas re-scales under the finger. "Updating…" floats over the top of the canvas instead of pushing it down, and the hint bar under it is a fixed two lines.
  • The hint bar says "Tap a part to see its spacing. Press and hold to drag it." with nothing selected, and "String · press and hold to drag it, or a ○ handle onto another part to attach it there" with a part selected.
  • No pinch zoom (use the − / + and Fit buttons), no long-press callout, no text selection on the canvas.

Reordering lists

  • A row with a grip (the rules in Spacing) drags at once by its grip, up or down; a 3px link bar shows where it lands.
  • Items without a grip, such as the "relative to" bases in Spacing, use press and hold. An outline in link grows from 0 to 3px over the hold (from about 100ms, whole under reduced motion), then the item lifts with a link edge and shadow-drag, and a 3px link bar shows where it lands. A quick tap still opens the item.
  • No HTML drag and drop on a phone.

"Needs a computer" note

In place of a tool that needs a computer, show the NeedsComputer note: a Banner in info with the monitor icon and these words, the tool's name first:

The glyph editor needs a computer. It's made for a mouse and a big screen. Open this page on a computer, or open it here anyway.

  • Actions: a primary Copy link (it copies the page's address and says "Link copied. Open it on a computer."), Back (Close when the note sits inside a dialog), then a quiet Open anyway on the far side. Open anyway lasts for this visit only; a reload shows the note again.
  • The glyph editor's note shows the glyph above it, drawn at 120px on bg-canvas, so the person still sees what they came for.
  • Tool names in use: "The glyph editor", "Review", "Making a release", "Importing and exporting the design". A screen with no declaration says "This screen needs a computer."

Lists, tables and sidebars

  • Tables become cards. A Typing card shows the glyph at 40px, its id in mono, each spelling with its field's label in caption, and any issue as an icon plus its words (status-danger for a clash, status-draft for a warning). A tap opens the glyph's card.
  • Detail cards cover the list, with a sticky bar on top: "← All glyphs" and the glyph's id. The glyph's spellings are edited there, in the same fields as on desktop.
  • Sidebars become selects above the content (the Glyphs area list becomes an Area select and a Typing filter select).

Typing areas

Where you type words to try them (Build & test), the words come first and the typing box, three rows tall, is docked under them, so you see what you type. The build and font settings fold into one summary line, such as "No build yet · Test the design", that opens them.

Long pages

A long page's contents are one sticky line: "Contents" in ink-muted and the current section's name in display. It opens a dropdown of 44px rows; the current row has a 3px sel-border left edge and sel-bg. A jump lands just below the sticky line.

Bottom action bars

A screen whose one main action must stay in reach while its list scrolls puts it in a bar at the bottom, with a count on the left: "2 ready to send · 1 sent" and Send Change Request…. Use it for that one action only; everything else stays in the list.

Checking

The phone check opens every phone screen at 390 × 844 with touch. It fails a screen that scrolls sideways, a button without words or an aria-label, or a target under 24px; a screen that needs a computer must show the note. Help screenshots stay desktop-only; the help says in words what differs on a phone.

Layout and density

Shell. Top bar (bg-panel, 48px): name, mode tabs (Glyphs, Layouts, Build & test, Review, Help), state pill, undo/redo, Save. Below: left dock, canvas, right dock, on bg-app with space-4 gaps.

Docks. A dock is a stack of panels. Each panel has a drag grip, a disclosure, a panel-title, a count chip and a ⋯ menu. Panels reorder by dragging and collapse to their header. Dock widths run dock-min…half the window; default dock-default.

Tables. Rows are control-md tall at default density, control-lg at comfortable. Header in label, rows ruled by hairline, selected row sel-bg with a sel-border ring. Spellings in mono; Chinese cells in cjk-label.

Breakpoints. ≥1100px: both docks. 760–1100px: one dock at a time, switched by tabs above the canvas. <760px (max-width: 759.98px), a phone: a one-row top bar and bottom tabs, one column with the canvas pinned on top and the panels as sections under it, tables as cards, sidebars as selects, every control one size up with main targets at control-touch (44px). The full rules are in phone.md.

Keyboard. Every dock action has a shortcut shown in its tooltip; ⌘Z / ⇧⌘Z undo and redo; ⌘S saves. Show shortcuts in code-sm.

States

Each state has one colour, one icon and one word. Never show one without the others.

State Token Icon Word Where
Saved status-saved ✓ Saved Top bar, glyph and layout headers.
Unsaved change status-draft ● Unsaved Top bar and the changed item; a dot on the tab. On a phone, the Save bar above the tabs.
Draft (not in the real font) status-draft, dashed pill edge ◌ Draft Items that exist only in the working file.
In the real font status-saved, solid pill edge ✓ In font Items that shipped in the last build.
Spelling clash status-draft ! Clash Typing sheet cell, with the other item named.
Conflict status-danger × Conflict Review and sync; offers Keep mine / Keep theirs.
Build running status-info ◐ Building Test & Build; shows steps, not a bare spinner.
Build failed status-danger × Build failed Banner with the failing item and a link to it.
Disabled ink-faint Controls only; the reason is in a tooltip.

Draft is dashed, real is solid: the line style carries the difference when colour cannot. The top bar's rules summary ("1229 rules · 46 KB") takes the pill of the strongest state present.

Undo and redo are always visible in the top bar. The one exception is a phone: its one-row top bar shows them only on Glyphs and Layouts, where edits happen. Other screens leave them out, and a toast that reports a change still offers its own Undo. Navigating away with unsaved changes asks once, in a dialog that names what is unsaved.

Success and failure are never told apart by green and red alone: jade and cinnabar differ in lightness, and each carries its icon and word.

Canvas and overlay vocabulary

The canvas shows one composed character on bg-canvas, drawn in glyph. Everything else is an overlay in the ov-* colours and sits above the glyph, never beneath it. Overlays are thin; the glyph stays readable through them at 100%.

Overlay Token Stroke Meaning
Part box ov-part + ov-part-fill 1px solid An ordinary component's box, tagged with its id in caption (hui, jc, zhu).
Anchor ov-anchor + ov-anchor-fill 2px solid The part everything else is placed against. Tag reads anchor. One per character.
Active part ov-active 2px solid, round handles The part being edited. Handles are handle-size circles filled ov-handle with an ov-active ring.
Area frame ov-area + ov-area-fill 2px solid A named area or group, and the edge a spacing rule measures from (drawn as a thick bar on that edge).
Measurement ov-measure 2px solid line, arrow ends A gap in units, labelled -120 (rule 3) in caption. Positive overlaps, negative leaves space.
Guides ov-guide 1px dashed Em box, baseline, centre lines. Hidden unless "boxes" is on.
Before ov-before 55% weight outline Review only: the old shape. Label says Before.
After ov-after solid outline Review only: the new shape. Label says After.

Rules:

  • Overlay colours are told apart by lightness and by shape (solid, dashed, handles) as well as hue; every tag carries a word.
  • Tags use caption, bg-panel at 85% behind the text, radius-sm, and sit on the box's top-left corner outside the glyph when they can.
  • Selection on the canvas is the active-part treatment only. Do not tint the glyph itself.
  • Thumbnails (16, 24, 32, 64px) show the glyph with no overlays, on bg-canvas, with a hairline edge. A selected thumbnail gains a sel-border ring and sel-bg surround, not a changed glyph colour.
  • Glyph strokes are glyph. A highlighted component inside a glyph or spelling is glyph-hi.
  • A hint bar under the canvas, in small and ink-muted, says what dragging does right now: "String · drag to change its active rule". On a phone it says "String · press and hold to drag it, or a ○ handle onto another part to attach it there", and "Tap a part to see its spacing. Press and hold to drag it." with nothing selected; it is a fixed two lines tall.
  • Zoom runs 25–400% with Fit; stroke widths stay in screen pixels at every zoom.

By touch

On a phone (below 760px) the canvas has to share the finger with scrolling. Full rules: phone.md.

  • A swipe scrolls the page; a tap selects a part on release and opens its Spacing.
  • Press and hold 400ms (8px of slop) lifts a part. A hold ring 60px across fills around the finger in ov-active, 4px wide, from about 100ms; under reduced motion it appears whole.
  • A lifted part takes a 4px ov-active outline, a sel-bg fill and shadow-drag, with a short vibration where the phone allows it. Release is one undo step.
  • Handles follow the same hold and get a 24px target around the drawn handle-size circle.
  • Nothing floats over the finger: the gap shows in the measurement label and the hint bar. "Updating…" floats over the canvas, and nothing around the canvas changes size during a drag.
  • No pinch zoom (the zoom buttons do it), no long-press callout, no text selection.

Components

Banner

Info, unsaved, failure, success

Use Banner for a state that stays true until fixed: a clash, a failed build, a draft notice.

  • Full tinted ground with a 1px edge in the state colour, an icon, a bold lead line and one sentence. Text is ink; only the icon and edge take the state colour.
  • Place it at the top of the affected panel or screen. It must name the item and link to it.
  • Dismissible only for info; warnings and failures go away when fixed.
  • Use Toast for something that just happened and needs no follow-up.

Button

Primary, default, quiet, danger, disabled

Use Button for every action that does something; use a link for navigation to another place.

  • One primary per view or dialog (Save, Build font, Keep). It fills with ink and reads bg-panel on it.
  • Default buttons carry a 1px border-strong edge. quiet has no edge and is for Cancel and toolbar actions.
  • danger (cinnabar text and edge) only for actions that discard work; a dialog confirms them.
  • Label is a verb in sentence case, with a Chinese gloss only when the item itself is Chinese. Heights: sm 24, default 28, lg 36 (first-run screens).
  • On a phone (below 760px) every height is one size up: sm 28, default 36, lg 44 (control-touch). Icon-only buttons are 44px wide. Nothing tappable is under 24px; main actions are 44px.
  • There is no hover on a phone: a tooltip shows for a moment after the tap, so an icon-only button must also carry an aria-label, and anything a person must read before acting belongs in the label, not the tooltip.
  • The consumer provides the label and the click handler; disabled buttons say why in a tooltip.
  • Do not put two primaries side by side; do not use colour alone to mark Skip vs Keep.

CanvasOverlay

Part boxes, anchor, active handles, measurement

Use CanvasOverlay vocabulary to draw anything on top of a composed glyph; the full table is in canvas-and-overlays.md.

  • Part boxes: 1px ov-part. Anchor: 2px ov-anchor with an anchor tag. Active part: 2px ov-active with round handles. Area frame: 2px ov-area with a thick bar on the measured edge. Measurement: 2px ov-measure with the number and rule in caption.
  • Guides are dashed ov-guide and hide when "boxes" is off.
  • Overlays sit above the glyph and stay thin so the glyph reads at 100%; stroke widths do not scale with zoom.
  • The preview uses a stand-in character; the consumer provides real glyph artwork, part rectangles and measurements in font units.

Chip

Filters, selected, dashed any, count

Use Chip for a small choice, filter or tag inside a row: "Used in" lists, glyph names, rule conditions.

  • Pressed chips fill sel-bg with a sel-border edge; unpressed chips keep the border-strong edge.
  • A dashed chip means "any / not set / add": a placeholder, not a value.
  • A count chip is quiet and not clickable.
  • Chinese and Latin go in one label (泛音 fy), Chinese first. The consumer provides the label and aria-pressed.
  • Chips are for choices; statuses use StatusPill.

Dialog

Confirm discard, over a scrim

Use Dialog only when work cannot continue until the person decides: discarding changes, replacing a glyph, publishing.

  • Title is a question or a plain statement in heading; body says what happens to what, with counts.
  • Footer, right-aligned: quiet cancel, optional danger, then one primary. The safe action is never the danger one.
  • Scrim is dark in both themes; the dialog uses shadow-modal and z-modal. Escape cancels; focus starts on the safe action and is trapped.
  • The consumer provides title, body and actions. Prefer a Banner or Toast for anything that does not block.

FormField

Text, mono, invalid, pill, checkbox

Use FormField to pair a label, a control and one help or error line for any input.

  • Labels sit above, in label; help is small in ink-muted; errors are small bold in status-danger with a × and a fix.
  • Controls are control-md high with a border-strong edge and a visible 2px focus ring. Mono for spellings and ids; the pill, sans-cjk input is only for typing Chinese or ASCII to preview.
  • Invalid state sets aria-invalid and shows the message; do not rely on the red edge.
  • Number fields show units (350 × 350). The consumer provides label, value, validation message.

GlyphTile

Thumbnails from 16px to 64px, selected

Use GlyphTile wherever a glyph appears as a picture: library grids, rule rows, review cards, the Structure list.

  • The tile is bg-canvas with a hairline edge, the glyph in glyph, and no overlays. A selected tile gains a sel-border ring; the glyph colour never changes. A highlighted component uses glyph-hi.
  • Common sizes: 16, 24, 32, 64 px art. The id beneath is code-sm in ink-muted.
  • The preview uses stand-in Chinese characters: real glyphs come from the JianZiPu font file and are drawn in the same ink.
  • The consumer provides the glyph (font text or SVG path), size and selected state.

NavTabs

Desktop top bar; on a phone, one row on top and tabs at the bottom

Use NavTabs for the screens of the app: in the top bar on desktop (Glyphs, Layouts, Build & test, Review, Help), and as bottom tabs on a phone.

  • Name in display at left, with the cinnabar seal stamp once (one character, reversed type) as the only use of solid accent in the bar.
  • The current tab fills sel-bg with a sel-border edge and sets aria-current="page".
  • Right side: the strongest StatusPill, undo and redo, then the one primary Save. Review is shown only in the local Builder; online, Your Change Requests sits in the More menu.
  • Below 760px the top bar is one 48px row: the seal, the screen's name in display at 22px with an ellipsis, a short StatusPill ("Saved"), Undo and Redo on Glyphs and Layouts only, and More. More holds the draft or local-files note, the font budget, the import and export items and the account.
  • Below 760px the tabs move to the bottom: 56px tall plus the safe area, a 20px icon over a caption word, in ink-muted. The current tab is ink on sel-bg with a 2px sel-border top edge. The tabs are Glyphs, Layouts, Try (Build & test), Requests (online only) and Help.
  • On a phone a 52px Save bar sits above the bottom tabs only while something is unsaved. The tabs and the Save bar step aside while the keyboard is open, and toasts sit above them. See phone.md.

NeedsComputer

On a phone, in place of a tool: the glyph editor, and inside a dialog

Use NeedsComputer on a phone, in place of a tool that needs a mouse and a big screen, to say so and offer a way on.

  • It is a Banner in info with the monitor icon (Lucide monitor), the tool's name in the bold lead line and one fixed sentence: " needs a computer. It's made for a mouse and a big screen. Open this page on a computer, or open it here anyway."
  • Actions, in this order: a primary Copy link with the link icon (it copies the page's address and the toast says "Link copied. Open it on a computer."), then Back with the back arrow, then, on the far side, a quiet Open anyway. Inside a dialog, Close takes Back's place.
  • Open anyway lasts for this visit only; after a reload the note shows again.
  • Show the thing the person came for above the note when there is one: the glyph editor's note has the glyph drawn at 120px on bg-canvas with a 1px border and radius-lg.
  • Tool names in use: "The glyph editor" (also New glyph), "Review" (apart from a tester's Your changes), "Making a release", "Importing and exporting the design". A screen that declares nothing says "This screen needs a computer."
  • Only below 760px. It never shows on desktop, and it is not an error: no danger, no dialog of its own. The consumer provides the tool's name, the key Open anyway remembers, and the glyph if any. See phone.md.

Panel

Dock panel with grip, count, rows

Use Panel for each dockable block in the Layouts side docks: Word types, Structure, Spacing, Centering, Area Properties.

  • Header: drag grip, disclosure, panel-title (EB Garamond), optional count chip, ⋯ menu. Collapsing hides the body and keeps the header.
  • Edge is a 1px border and radius-lg; no shadow while docked, shadow-drag only while being dragged.
  • Rows inside use sel-bg and sel-border for the selected one; secondary lines are mono ids in ink-muted.
  • The consumer provides the title, rows and menu items; panel width is the dock's, never fixed by the panel.
  • On a phone (below 760px) the docks become one column: the canvas pinned on top at min(52dvh, 460px) and every panel a section under it, in a fixed order with the one a tap opens first (Spacing on Layouts, Selection in the glyph editor). No grip, no moving between docks, no resizing; the header is 44px and folds the section. Tapping a part opens its panel and scrolls it in just under the canvas. See phone.md.

ReviewItem

Before and after, keep or skip

Use ReviewItem in Review, one per proposed change, for the maintainer to keep or skip.

  • Header names the item and the state (Proposed, Conflict). Body shows Before and After side by side: Before has a dashed ov-before edge, After a solid ov-after edge, and each is labelled in words. A toggle overlays them on one canvas, Before at 55% weight.
  • Changed spellings and spacing show as mono before → after beneath the pictures.
  • Footer: Skip then Keep (primary). Keeping is undoable via Toast.
  • The consumer provides the glyph artwork for both versions and the change details.

RuleRow

Spacing rules in order, one selected

Use RuleRow for one condition in a spacing rule list ("when String · Right hand is …"). Rules are tried top to bottom; the first match wins.

  • Anatomy: drag handle, numbered circle, any dashed chip (or a named condition), the glyphs it matches as small GlyphTiles.
  • The selected rule uses sel-bg and sel-border, and is the rule drawn on the canvas as the measurement.
  • The fallback row is dashed: "otherwise: none set" in status-draft means a gap in coverage and says so.
  • The consumer provides the ordered rules and handles reorder.

StatusPill

Saved, draft, conflict, building

Use StatusPill for the state of an item or the whole file: Saved, Unsaved, Draft, In font, Clash, Conflict, Building, Build failed.

  • Always icon plus word; colour is the third signal, never the only one.
  • Draft pills have a dashed edge and real (in-font) pills a solid one; keep that difference.
  • One pill per item. The top bar shows the strongest state present (danger over draft over saved).
  • The consumer provides the state and, optionally, a count or detail after the word.

Table

Typing sheet with a clash and a selected row

Use Table for the typing sheet and any list of records compared across columns.

  • Header label with a border-strong rule; rows ruled by hairline; hover bg-hover; selected sel-bg.
  • Spellings in mono; Chinese in the table face; Traditional cells carry lang="zh-Hant".
  • A clash cell fills status-draft-bg, shows !, and names the other item in words.
  • Row height is control-md. At narrow width each row becomes a card with the header labels inline.
  • The consumer provides columns, rows and the state per row.

Toast

Saved, with undo

Use Toast for a quick confirmation of something that already happened: Saved, Skipped, Copied.

  • bg-bar with on-bar text, radius-lg, shadow-float, z-toast; bottom-centre, auto-dismiss after 5 seconds, paused on hover and focus.
  • Max one action, always Undo when the action can be undone. Never use for errors: use a Banner.
  • The consumer provides one short sentence, with counts.
